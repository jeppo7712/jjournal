# Contributing

Contributions are welcome — bug fixes, features, docs, whatever.

## Before you start on something bigger

For anything more than a small fix, please open an issue first describing what you want to change and why. It's a lot easier to align on an approach before code is written than to rework a finished PR.

## Making a change

1. Fork the repo and branch off `main`.
2. Make your change. Keep PRs focused — one logical change per PR is much easier to review than a bundle of unrelated fixes.
3. Open a pull request describing what changed and why. Please don't just push to a personal fork and go quiet — the goal is for useful changes to make it back here, not to fragment into disconnected copies.
4. I'll review it, might ask for changes, and will merge or explain why not.

## Reporting bugs / suggesting features

Open an issue. Include what you expected, what happened instead, and (for bugs) relevant server log output if you have it.
